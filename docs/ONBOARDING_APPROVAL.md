# Onboarding and approval slice

Platform owners issue operator invitations with a club identity; managers issue member invitations for their own club. Links expire after 72 hours, are stored as SHA-256 hashes and can be revoked. Possession plus matching email permits a new account; existing accounts must sign in and cannot have their password changed by an invitation. Acceptance is atomic and single-use. Operator acceptance creates the club and manager grant; member acceptance grants only member access. Links are manually shared, not automatically emailed; do not describe email ownership as independently verified. Never log or commit raw invitation links.

Members save a dog profile, then separately submit a grooming application with emergency contact and handling notes. Drafts remain visible only to the dog owner; managers gain access after submission. Draft, pending, needs-information, approved, expired and suspended are separate review states. Decisions require a manager of that club, a reason and a version match; record reviewer/time/reason. A request for more information permits resubmission; suspended/expired/approved records require manager handling. Approval applies only to grooming and does not establish payment, booking or venue admission. Social visibility remains owner-controlled. No real-customer rollout until broader care/document requirements are completed.

Acceptance: operator with no account joins, new member joins only the invited club, saves dog, submits application, manager approves, member sees result. This complete journey passed in the local browser on 25/09/2026. Negative tests cover private drafts, invite expiry/reuse/revocation, wrong existing account, privilege escalation, cross-club access, private care reads and stale approval. Local database only until migration review and deployment.
